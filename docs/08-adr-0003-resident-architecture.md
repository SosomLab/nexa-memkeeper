# 08 · ADR-0003 — 상주 최소화 구조 (셸 / 온디맨드 기능)

> 상태: **📐 제안 — 사용자 판단 대기.** 핵심 요구 "기능은 상주하지 않는다 — 수행 시 점유, 종료 시 회수"([00 §1](00-vision.md))의 구현 방식 결정.
> **정정(08-07)**: 최초 권고는 A(단일 프로세스 — 복잡도 근거)였으나, **DR-4(성능·동작 안정성 > 개발 편의)** 확정에 따라 §3을 **하이브리드 권고로 정정**. 원래 판정문은 §3에 취소선으로 보존.

## 1. 문제

상주부(트레이+관찰)는 항상 떠 있고, 기능부(Top 5 팝업·트리 뷰·정리 실행)는 간헐 사용된다.
기능부가 쓴 메모리(열거 버퍼·UI 리소스·폰트·창)를 어떻게 확실히 되돌려 유휴 RSS ≤5MB를 유지하는가.

## 2. 후보 비교

| | A. **단일 프로세스 + 지연 로드 + 자기 트림** | B. 셸 + 온디맨드 워커 프로세스 분리 |
| --- | --- | --- |
| 구조 | 프로세스 1개. 기능 모듈은 첫 사용 시 초기화, 창 닫으면 힙 해제 + `EmptyWorkingSet(self)` | 상주 셸 exe + 기능 실행 시 자기 exe를 `--worker` 인자로 재기동, 종료 시 프로세스 소멸 |
| 회수 보장 | 힙 해제분은 allocator가 OS 반환(디커밋) + 워킹셋 트림 — **커밋은 allocator 정책 의존**(대부분 반환되나 100% 보장은 아님) | **100% 보장** — 프로세스 종료 = OS가 전부 회수 |
| 유휴 RSS | 5MB 목표 달성 가능(트림 후 3~5MB) | 셸이 더 작아짐(2~3MB — UI 코드 페이지가 유휴 시 워킹셋 밖) |
| 복잡도 | **낮음** — 상태 공유 자유, IPC 없음 | 높음 — IPC(설정·명령·결과), 창 소유권·포커스 처리, 프로세스 수명 관리 |
| 기능 창 기동 속도 | **즉시**(<100ms — NFR-4 유리) | 프로세스 spawn ~50-150ms + 초기화 — NFR-4 빠듯 |
| 정리 엔진 위치 | 같은 프로세스(짧은 워커 스레드) | 워커 프로세스 — 정리 도중 자기 점유가 셸 수치에 안 섞임 |
| 실패 격리 | 기능 크래시 = 전체 크래시 | 워커 크래시에도 셸 생존 |

## 3. 판정 — 정정(08-07, DR-4 반영)

~~최초 판정: 기능부가 작아 IPC·수명 관리 복잡도가 B의 이득을 초과 — A 권고, NFR-3 실측 실패 시 B 전환.~~
→ **정정**: 위 판정의 A 우위 근거는 "복잡도"(= 개발 편의)였다. **DR-4(성능·동작 안정성 > 개발 편의)** 기준으로 다시 판정한다.

- **동작 안정성**: B가 구조적 우위 — ① 메모리 회수 **100% 보장**(allocator 정책 의존 없음 = NFR-3이 검증 대상이 아니라 구조적 귀결) ② 미문서 NT API·타 프로세스 조작이 일어나는 정리 엔진과 대량 열거가 **워커에서 크래시해도 상주 셸 생존** ③ 상주 셸은 코드 경로가 극소(트레이+타이머)라 자체 크래시 면적 최소.
- **성능**: 유일한 B 열세는 워커 spawn 지연(~50-150ms)인데, 이는 트리 뷰(NFR-4 예산 300ms)·정리 실행(수 초 작업)에는 무해. **빈번·즉시성이 필요한 Top 5 팝업만 셸에 남기면** 성능 열세가 소거된다(팝업은 열거 1콜+소형 팝업 — 크래시 면적 작음).

**권고(정정): 하이브리드 — 상주 셸(트레이·관찰·Top 5 팝업) + 온디맨드 워커 프로세스(트리 뷰 창·정리 엔진, 자기 exe `--worker` 재기동, 종료 = OS 전량 회수).**
IPC는 최소로: 명령 = 커맨드라인 인자, 결과 = 종료 코드 + 공유 파일 매핑(또는 `WM_COPYDATA`) 1채널. 설정은 양쪽 다 `data\settings.ini` 직접 읽기(쓰기는 셸만).

## 4. 동작 규칙 (하이브리드)

1. 상주 셸 루프 = 트레이 아이콘 + 5초 타이머(`GlobalMemoryStatusEx`) + 메시지 대기 — 그 외 아무것도 초기화하지 않는다(폰트·브러시·열거 버퍼도 지연).
2. Top 5 팝업은 셸 내 지연 초기화 — 닫힘 시 리소스 해제 + `EmptyWorkingSet(self)` 1콜(자기 최적화는 기능 데모이기도 하다).
3. 트리 뷰·정리 실행 = 워커 프로세스 기동 → 완료/창 닫힘 시 프로세스 종료. 셸은 종료 코드·결과만 수신해 툴팁/알림 갱신.
4. 워커 비정상 종료(크래시·타임아웃) 시 셸은 결과 "실패" 통지 후 정상 지속 — 상주부는 어떤 기능 실패에도 죽지 않는다.
5. 승격이 필요한 정리 영역(②~⑥)은 **워커만 승격**하는 선택지 확보 — 셸은 항상 일반 권한 유지 가능(공격 면적 최소화).
