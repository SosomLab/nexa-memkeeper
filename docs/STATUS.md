## 2026-08-08 6차 — X-1: 워치리스트 표적 트림

- `[watch] entries = chrome.exe:1500` 형식으로 **지정 프로세스만** 임계 초과 시 트림. 전역 정리의 비용 없이 비대화된 앱만 겨냥한다.
- 꺼져 있으면 **열거조차 하지 않는다**(유휴 비용 0). 켜면 가벼운 열거(시스템 콜 1회) + 프로세스별 쿨다운 + 보호 목록 준수.
- 검증: `code.exe:300`으로 첫 주기에 표적 포착 → 다음 주기에 임계 아래(트림 성공). 테스트 **57 green**.
- UI는 미구현(파일 설정) — 목록 편집 UI는 후속.

## 직전(2026-08-08 1차) — E-1: 알림에 Active 감소분 병기

- 알림이 **두 숫자를 함께** 보여 준다 — `935MB reclaimed · apps released 5519MB`(이번 실행 실측).
- 기존 표기(Avail 차)는 트림이 Modified로 밀어낸 몫을 놓쳐 **실제의 1/5도 설명하지 못했다**([21 §2-1](21-effectiveness-measurement.md)).

- Active 감소분이 표시값과 비슷하면 병기하지 않는다(숫자 나열 방지). 측정 실패 시에도 병기 생략.

  — 걷어낸 페이지를 프로세스가 곧바로 되찾아간다(VS Code 667 → 40 → **717MB**).
- 주기 정리(60초): Available +688MB를 얻는 대신 앱 기동 **+4.3%**, 파일 읽기 **+12.6%** 악화.
  개선된 성능 지표는 **하나도 없음**. 압력 하 선제 정리도 무의미(4GB 할당 차이 1.2% < 편차 1/12).
