# 15 · 개발 방법론

> `nexa-dir2` 검증 규율 전면 계승(DR-2). 문서·커밋/푸시 세부는 [16](16-doc-git-conventions.md)이 SSOT, 여기는 개발 진행 방식 + 이 프로젝트 고유 규약.

## 1. 진행 규율

- **수직 슬라이스** — 단위는 항상 "관찰·테스트 가능한 얇은 끝단"(UI에 보이거나 테스트가 도는 것). 레이어 단위 작업 금지.
- **단위 = 커밋 1개** · **초안 먼저, 확장은 별도 커밋** · **main 항상 green**(테스트·clippy·fmt 통과 전 병합 금지 — [18](18-build-and-test.md)).
- **예산 게이트 우선(DR-8)** — 기능보다 예산. 마일스톤 완료 전 실측, 초과 시 병합 금지.
- **기존 자산 우선** — Win32 창·컨트롤·패키징은 `nexa-dir2` 코드를 먼저 확인 후 이식(재발명 금지). 이식 커밋 본문에 원본 경로 명기.
- 사용자 개입 최소화로 자동 진행(파괴적 작업·push 제외 — [16 §4](16-doc-git-conventions.md)).
- 자동 진행·고지·질문의 경계와 개발/협업 세션 분담은 [22](22-session-and-automation-rules.md)가 SSOT.

## 2. commit scope 규약 (확정 — [16 §3](16-doc-git-conventions.md)의 이 프로젝트 인스턴스)

| scope | 영역 |
| --- | --- |
| `core` | mk-core — 순수 로직(계산·모델·설정 파싱) |
| `shell` | 상주 셸 — 트레이·타이머·Top 5 팝업 |
| `worker` | 온디맨드 워커 — 트리 뷰 창·정리 엔진 실행 |
| `app` | mk-app 공통 — 진입점·Win32 기반·프로세스 기동/IPC |
| `pkg` | 패키징·배포 산출물 |
| `ci` `docs` `test` | 통상 의미 |

예: `feat(shell): 트레이 아이콘 사용률 표시(M0-1)` · `fix(worker): 보호 프로세스 열거 플래그 누락(사용자 QA)`

## 3. 크레이트 구조 (DR-5·DR-7 반영)

- `crates/mk-core` — **rlib, 플랫폼 독립** 순수 로직. 단위 테스트는 전부 여기(비Windows에서도 `cargo test` 가능).
- `crates/mk-app` — **bin 1개**(셸·워커 겸용 — `--worker` 인자로 분기, DR-7). Win32는 `#[cfg(windows)]` 격리. windows crate features는 최소만 열고 필요 시 추가.
- 전부 정적 링크 = 단일 exe. 크레이트 추가(분리)는 DR 정정으로만.

## 4. 안전 규율 (이 프로젝트 고유)

- **상태를 바꾸는** 호출 — 타 프로세스 핸들 획득(`OpenProcess`)·트림·종료·`NtSetSystemInformation` — 은 **워커 경로에만** 둔다(DR-7 격리 원칙).
  - **정정(08-07, M2)**: 최초 규칙은 "미문서 NT API 전부 셸 금지"였으나 [ADR-0003 §3](08-adr-0003-resident-architecture.md)이 Top 5 팝업을 셸에 두기로 한 결정과 충돌한다. → **읽기 전용 조회**(`NtQuerySystemInformation`)는 셸 허용: 부작용이 없고 팝업 즉시성(NFR-4 <100ms)에 워커 spawn을 낄 수 없다. 대신 버퍼 워킹은 **경계 검사 필수**(오프셋·길이를 매 항목 검증, 실패 시 조기 중단).
- 보호 프로세스([05 §4-4](05-requirements.md)) 검사는 열거 단계에서 수행 — 종료·트림 함수는 보호 플래그 인자를 강제 받는 시그니처로 설계(우회 불가).
- `unsafe` 블록에는 안전 조건 주석 필수. 새 시스템 콜 도입 시 [07](07-adr-0002-memory-reclaim.md) 표에 행 추가(같은 커밋).
- **기다리는 일은 UI 스레드 밖으로.** 프로세스 종료 대기·열거 같은 블로킹 작업을 창 프로시저에서 직접 하면 "응답 없음"이 된다. 백그라운드 스레드 + 완료 메시지(PostMessage)로 처리한다(08-07 QA — journal 24차).
- **UI 헬퍼는 창 상태를 인자로 받는다.** `thread_local! RefCell` 상태를 헬퍼가 스스로 다시 빌리면, 이미 `with_state(...)` 안에서 호출됐을 때 **이중 대여 패닉 → `panic=abort`로 창이 즉시 사라진다**(08-07 QA 사례 — journal 22차).
- 리소스 획득/해제는 쌍으로 리뷰 — NFR-3(기능 종료 후 유휴 복귀)이 실측 게이트로 누락을 드러낸다.
