# 05 · 요구사항 — FR / NFR / 설정 스펙

> FR = 기능 요구, NFR = 예산·품질 게이트([00 §3](00-vision.md) 제안 수치 연동), §4 = 설정 스펙(주요 메모리 정리 프로그램 차용 + 추천 기본값).
> 구현 상태는 [MILESTONES](MILESTONES.md)에서 추적, 여기는 스펙만.

## 1. 기능 요구 (FR)

### FR-1 트레이 상주 셸
- 시스템 트레이 아이콘 상주. 아이콘에 **현재 메모리 사용률 %** 를 실시간 표기(텍스트 렌더 아이콘, 색 단계: 정상/주의/위험).
- 툴팁: 사용률·사용량/전체·마지막 정리 시각·회수량.
- 더블클릭(또는 설정된 동작): 즉시 정리 실행.

### FR-2 Top 5 팝업 (트레이 클릭)
- 좌클릭 → 소형 팝업: **메모리 점유 Top 5 프로세스**(이름·PID·프라이빗 워킹셋)를 내림차순 표시 + 전체 사용률 요약 줄.
- 팝업에서 항목 우클릭 → 해당 프로세스 워킹셋 트림 / 종료(확인 후).
- 팝업 하단: [지금 정리] [목록 보기…] [설정…] 버튼.

### FR-3 프로세스 트리 뷰 (목록 보기)
- 별도 소형 창. **프로세스 트리**(부모→자식) + 각 프로세스 펼침 시 **하위 쓰레드** 표시.
- 열: 이름 / PID(TID) / 프라이빗 워킹셋 / 워킹셋 / 상태. 정렬·간단 필터(이름 검색).
- 선택 프로세스에 대해: **정상 종료 요청(WM_CLOSE) → 강제 종료(TerminateProcess)** 2단계, **워킹셋 트림**(종료 없이 회수).
- 보호 목록(§4-4)의 시스템 프로세스는 종료 명령 비활성 + 경고 표시.
- 창을 닫으면 관련 메모리를 해제하고 자기 워킹셋을 트림해 유휴 수준 복귀(NFR-3).

### FR-4 메모리 정리 엔진
- 정리 영역(각각 on/off, [ADR-0002](07-adr-0002-memory-reclaim.md)):
  ① 프로세스 워킹셋 트림 ② 우선순위 0 스탠바이 리스트 퍼지 ③ 전체 스탠바이 리스트 퍼지
  ④ 수정 페이지 리스트 플러시 ⑤ 시스템(파일캐시) 워킹셋 ⑥ 페이지 결합(memory combining).
- 트리거: 수동(트레이/팝업/핫키) · **임계값 자동**(사용률 ≥ N%) · 주기 자동(N분) · 저메모리 이벤트(옵션).
- 정리 후 결과 통지(회수량 MB) — 토스트/툴팁, off 가능. 쿨다운(최소 간격)으로 과도 실행 방지.

### FR-5 설정
- 트레이 우클릭 메뉴: 자주 쓰는 토글(자동 정리 on/off·Windows 시작 시 실행·알림 on/off) + [설정…] 창.
- 설정 창: 그룹 3개(자동 정리 / 정리 영역 / 일반) 단일 소형 창 — 탭 없음, §4 표의 항목만.
- 저장: exe 옆 `data\settings.ini`(포터블), 쓰기 불가 시 `%LOCALAPPDATA%\NexaMemKeeper\` 폴백.

### FR-6 권한 처리
- 일반 실행: 자기 프로세스·사용자 프로세스 트림 가능. 시스템 전역 퍼지(②~⑥)·타 세션 프로세스는 **관리자 권한 필요** — 메뉴에서 "관리자 권한으로 재시작" 제공.
- 시작 시 실행 + 승격이 필요한 경우: **작업 스케줄러 등록 방식**(UAC 프롬프트 없이 승격 시작 — Mem Reduct 방식 차용) 옵션.

## 2. 비기능 요구 (NFR — 예산 게이트)

| # | 항목 | 게이트 |
| --- | --- | --- |
| NFR-1 | 유휴 상주 RSS ≤ **5MB** · exe ≤ **3MB** · 외부 DLL **0** | 마일스톤마다 실측, 초과 시 병합 금지 |
| NFR-2 | 유휴 CPU ~0% — 관찰은 저비용 폴링(기본 5초) 또는 이벤트 구동 | 작업 관리자에서 0.0% 유지 |
| NFR-3 | 기능 창 사용 후 닫으면 RSS 유휴 수준 복귀 | 자기 트림 실증 |
| NFR-4 | Top 5 팝업 표시 < 100ms · 트리 뷰 첫 표시 < 300ms(프로세스 ~300개 기준) | 열거 1콜 설계([ADR-0002 §4](07-adr-0002-memory-reclaim.md)) |
| NFR-5 | 보호 프로세스 오조작 0 — 종료·트림 대상에서 하드 제외 | §4-4 고정 목록 |

## 4. 설정 스펙 (추천 기본값)

### 4-1. 자동 정리
| 설정 | 기본값 | 범위/선택지 | 비고 |
| --- | --- | --- | --- |
| 임계값 자동 정리 | **on, 사용률 ≥ 90%** | 50~95%, 5% 단위 | Mem Reduct 기본(90%) 차용 |
| 정리 쿨다운(최소 간격) | **5분** | 1~30분 | 임계값 진동 시 연속 실행 방지 |
| 주기 자동 정리 | **off** | 10분~4시간 | 임계값 방식과 중복 — 원하는 사용자만 |
| 저메모리 이벤트 트리거 | off | on/off | `CreateMemoryResourceNotification` 기반, 실험적 |

### 4-2. 정리 영역 (기본값 = 안전 우선)
| 영역 | 기본 | 부작용 표기(UI에 노출) |
| --- | --- | --- |
| ① 프로세스 워킹셋 트림 | **✅ on** | 재사용 시 소프트 폴트 — 안전 |
| ② 우선순위 0 스탠바이 퍼지 | **✅ on** | 저우선 캐시만 — 안전 |
| ③ 전체 스탠바이 퍼지 | ☐ off | ⚠️ 파일 캐시 소실 → 일시 체감 저하 |
| ④ 수정 페이지 플러시 | ☐ off | ⚠️ 디스크 쓰기 유발 |
| ⑤ 시스템 워킹셋 | ☐ off | ⚠️ 시스템 캐시 재적재 비용 |
| ⑥ 페이지 결합 | ☐ off | 효과 완만, 실행 시간 김 |

### 4-3. 일반
| 설정 | 기본값 | 비고 |
| --- | --- | --- |
| Windows 시작 시 실행 | off | on 시 승격 필요하면 작업 스케줄러 방식 안내 |
| 트레이 아이콘 표시 | 사용률 %(색 단계 80/90%) | 숫자/아이콘만 선택 가능 |
| 정리 완료 알림 | on(회수량 MB) | off 가능 |
| 전역 핫키(즉시 정리) | off | 예: `Ctrl+Alt+M` |
| 관찰 폴링 주기 | 5초 | 2~30초 |
| Top N 개수 | 5 | 3~10 |
| Top N 기준 | 프라이빗 워킹셋 | 워킹셋/커밋 선택 가능 |

### 4-4. 보호 프로세스 (하드 제외 — 종료·트림 금지)
`System(4)` `Idle(0)` `csrss.exe` `wininit.exe` `winlogon.exe` `services.exe` `lsass.exe` `smss.exe` `dwm.exe` `fontdrvhost.exe` + Protected Process(PPL) 전부 + **자기 자신**. 사용자 제외 목록은 여기에 추가만 가능(고정 목록 해제 불가).

## 5. 리스크

| 리스크 | 대응 |
| --- | --- |
| 스탠바이 퍼지 남용 → 체감 성능 저하 논란(메모리 클리너 일반 비판) | 기본값 안전 영역만 on(§4-2), 부작용 UI 명시, 문서화 |
| 승격 없이 전역 정리 불가 → 기능 절반 제한 | FR-6 승격 UX(재시작·작업 스케줄러) 제공 |

| Windows 업데이트로 미문서 API(NtSetSystemInformation) 동작 변화 | ADR-0002 §5 폴백 정의, 버전 체크 |
