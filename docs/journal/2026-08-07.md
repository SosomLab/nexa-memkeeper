## 22차 — 메뉴 토글 시 목록 창이 즉시 종료되던 버그 (사용자 QA)

**증상**: 메인 화면에서 **의사 프로세스 숨김을 해제**하면 UI가 멈추고 창이 사라진다. 트레이는 멀쩡하다.

**원인**: `RefCell` **이중 대여 패닉**. `sync_menu_checks`가 내부에서 `with_state_ret`으로 STATE를 다시 빌리는데, 호출부 4곳이 이미 `with_state(...)` **안**이었다.

```
with_state(|st| {                 // borrow_mut() 시작
    st.hide_pseudo = !st.hide_pseudo;
    sync_menu_checks(st.menu, …); // ← 내부에서 또 borrow_mut() → panic
});
```

릴리스 프로파일이 `panic = "abort"`(DR-4 성능 우선)이라 **스택 되감기 없이 프로세스가 즉시 죽는다**. 트레이가 멀쩡한 이유는 목록 창이 별도 워커 프로세스이기 때문 — **DR-7 하이브리드 격리가 의도대로 작동**해 셸까지 함께 죽지 않았다.

**영향 범위**: 의사 프로세스 숨김뿐 아니라 **보기 모드 전환·갱신 주기 변경·자동 실행 토글**도 같은 경로라 전부 같은 증상이었다(사용자가 그중 하나를 먼저 만난 것).

**조치**: `sync_menu_checks`가 STATE를 만지지 않도록 **필요한 값(flat)을 인자로 받게** 변경하고 호출부 5곳을 갱신. 함수에 "여기서 STATE를 다시 빌리면 안 된다"는 이유를 주석으로 남겼다.

**검증**: 이전에 죽던 메뉴 명령 9개(의사 프로세스 ×2 · 트리/평면 전환 · 1/2/5초 · 자동 실행 ×2)를 연속 실행 → **창 생존 확인**. 테스트 49 green.

**교훈**: 상태를 `thread_local! RefCell`로 들고 있으면, 헬퍼가 상태를 "알아서 읽는" 편의가 곧 이중 대여 함정이 된다. **UI 헬퍼는 상태를 인자로 받는다**를 규칙으로 삼는다([15 §4](../15-dev-methodology.md)에 추가).

## 19차 — 설정 창 라벨 줄바꿈 수정 (사용자 QA)

**증상**: "최소 간격 (ms, 60000~1800000)" 라벨이 2줄로 접혀 아래가 잘렸다(18차에서 단위를 ms로 바꾸며 문구가 길어진 여파).

**원인**: 라벨 폭이 170px 고정인데 문구는 173px 필요. STATIC 컨트롤은 기본이 자동 줄바꿈이라 넘치면 다음 줄로 접히고, 컨트롤 높이는 18px 고정이라 두 번째 줄이 잘려 보였다.

**조치**: 라벨/입력 칸 규격을 상수로 통일 — `LBL_W=218` · `NUM_X=232` · `NUM_W=96`. 자동 정리·일반 그룹의 모든 행이 같은 열에 정렬되고, 입력 칸도 7자리(1800000)를 여유 있게 담는다.

**검증 방법(교훈)**: 컨트롤 높이만 재면 줄바꿈 여부를 알 수 없다(높이는 내가 준 18px 그대로). `WM_GETFONT`로 실제 폰트를 얻어 `GetTextExtentPoint32W`로 **필요 폭**을 재고 컨트롤 폭과 비교해야 확실하다. 실측 결과:

| 라벨 | 필요 | 컨트롤 |
| --- | --- | --- |
| 최소 간격 (ms, 60000~1800000) | 173px | 218px ✅ |
| 관찰 주기 (ms, 2000~30000) | 155px | 218px ✅ |
| 목록 갱신 (ms, 500~10000) | 149px | 218px ✅ |
| 주기 정리 (ms, 0=끔) | 116px | 218px ✅ |
| 임계값 (%, 50~95) | 101px | 218px ✅ |

**부수 관찰**: 검증 중 창을 못 찾아 헤맸는데, ① PowerShell에서 `$script:` 스코프로 콜백 결과를 받아야 하고 ② 내가 띄운 설정 창을 사용자가 닫으면 당연히 사라진다는 두 가지가 겹친 것이었다. 코드 문제 아님.

## 18차 — 설정 시간 단위 ms 통일 (사용자 요청)

**무엇**: 설정 화면의 시간 값이 초·분·ms로 섞여 있던 것을 **전부 밀리초로 통일**.

| 항목 | 이전 | 이후 |
| --- | --- | --- |
| 관찰 주기 | `poll_secs` 5초 (2~30) | `poll_ms` **5000** (2000~30000) |
| 정리 최소 간격 | `cooldown_secs` 300초 (60~1800) | `cooldown_ms` **300000** (60000~1800000) |
| 주기 정리 | `interval_mins` 0분 (10~240) | `interval_ms` **0** (600000~14400000) |
| 목록 갱신 | `list_refresh_ms` 2000 | 그대로 |

**마이그레이션**(docs/09 §7-4 "키 개명 금지 — 신규 키 + 1회 마이그레이션"): 구 키를 읽으면 ×1000·×60000으로 환산해 새 필드에 넣고, 저장 시 새 키로만 쓴다. 구 키는 "모르는 키 보존" 대상에서 제외해 파일에 남지 않는다.

**실기 검증**: 구 버전 파일(`poll_secs=8`·`cooldown_secs=420`·`interval_mins=20`)을 두고 실행 → 설정 창에 8000·420000·1200000으로 표시 → 저장 후 파일이 `poll_ms = 8000`·`cooldown_ms = 420000`·`interval_ms = 1200000`으로 재작성됨을 확인. `should_auto_clean`도 ms 기준으로 바꾸고 테스트 갱신(**38 green**).

**부수 정리**: `interval_ms`는 0(끔)이거나 600000ms(10분) 이상만 허용 — 이전 분 단위 범위(10~240분)를 ms로 옮긴 것. 설정 창 라벨도 전부 `(ms, 범위)` 표기로 바꿨다.

## 15차 — "프로그램을 목록에서 찾을 수 없다" 원인·해결 + 앱 아이콘 (사용자 문의/요청)

**원인(실측)**: 버그가 아니라 **트리 기본 보기의 구조적 함정**이었다. `NexaMarkdownViewer.exe`(PID 35624)의 부모가 `explorer.exe`(PID 3200)라서 **explorer 노드가 접힌 상태에서는 자식이 화면에 없다**. 전체 491개 중 고아(부모가 이미 종료)는 82개뿐이라, **나머지 400여 개가 부모 아래 숨어 있었다** — 탐색기·셸에서 띄운 앱은 전부 여기 해당한다. M3에서 평면 목록을 트리로 바꾸면서 발생한 회귀.

**해결 3종**:
1. **기본 보기 = 평면 목록**(`build_rows_flat`) — 계층 없이 전부 나열(작업 관리자 "자세히"와 동일). 트리는 **보기 메뉴**에서 선택.
2. **보기(&V) 메뉴 신설** — 평면 목록 / 프로세스 트리(체크 표시) · 모두 펼치기 / 모두 접기 · 검색 지우기. "모두 펼치기"는 **자식 있는 프로세스만** 펼친다(전부 펼치면 쓰레드가 수천 줄이 된다).
3. **타이핑 즉시 검색** — 창에 그냥 입력하면 이름 부분 일치 필터(대소문자 무시), Backspace 한 글자, **Esc 전체 지움**. 검색 중에는 결과가 부모 아래 숨지 않도록 **항상 평면**으로 그린다. 상태 줄에 `🔍 검색 "..." — N개 일치` 표시. 별도 입력 상자 없이 처리(커스텀 드로잉 창 관용구).
- mk-core에 `build_rows_flat`·`filter_by_name` + 회귀 재현 테스트(트리에서는 1개만 보이고 평면에서는 3개 다 보이는 대비 검증) — **테스트 26 green**.

**앱 아이콘 신규**(사용자 요청 — nexa-dir2 형태 참조 + 메모리 회수·비율):
- `scripts/make-icon.ps1`(System.Drawing만 사용, 외부 도구 0)로 재현 생성 → `crates/mk-app/assets/nexa-memkeeper.ico`(9종 해상도 16~256) + 1024 PNG 마스터.
- 디자인: **nexa-dir2 계열 계승**(둥근 사각 + 파랑 외곽 `#3B82F6` + 남색 그라데이션 바디) + 이 앱 정체성 = **80% 도넛 게이지**(트레이 주의 임계와 같은 값) + **RAM 모듈 글리프** + **아래 화살표(회수)**, 초록 `#22C55E`.
- `build.rs`가 생성 .rc에 `1 ICON`을 추가해 **exe에 임베드**, 메인 창은 `LoadIconW(리소스 1)`로 제목 표시줄·작업 표시줄·Alt+Tab에 적용. 아이콘 파일이 없으면 경고만 남기고 빌드는 통과.
- 예산 영향: exe **0.41 → 0.47MB**(게이트 3MB 대비 여유), 상주 RSS 1.31MB 유지.

## 13차 — 권한 실측 답변 · 의사 프로세스 숨김 옵션 (사용자 문의/요청)

**질문 1: "관리자 권한으로 실행되어야 하나? 자동 시작되면서 설정이 가능한가?"** → 같은 PC에서 승격/비승격을 연속 실행해 실측하고 [07 §4](../07-adr-0002-memory-reclaim.md)에 표로 기록.

| | 일반 권한(제한 토큰) | 관리자 승격 |
| --- | --- | --- |
| 워킹셋 트림 | 115개 성공 / 378 제외 | **466개** / 25 제외 |
| 영역② 스탠바이 퍼지 | `0xC0000061`(PRIVILEGE_NOT_HELD) 실패 → partial | NTSTATUS 0 성공 |
| 회수량 | **+322MB** | **+847MB**(2.6배) |

→ **관리자 권한은 필수가 아니다.** 일반 권한으로도 관찰·목록·자기 세션 트림이 동작하고 실제로 회수된다. 승격은 "더 많이" 회수하기 위한 선택지이며, 생략된 영역은 알림에 명시된다.
자동 시작과 권한 관계도 [07 §4-1](../07-adr-0002-memory-reclaim.md)에 정리: 현재 구현(`HKCU\…\Run`, DR-11)은 **일반 권한 시작**이고 Windows 정책상 Run 키로는 승격이 불가능하다. 승격 자동 시작이 필요하면 **작업 스케줄러 "가장 높은 수준의 권한으로 실행"**이 표준 해법(FR-6에 계획, 미구현).

**요청 2: "의사 프로세스도 숨기는 옵션을, 기본은 숨김으로"** → 구현.
- mk-core `is_pseudo`/`filter_pseudo` + 테스트(숨김 대상 = Memory Compression·MemCompression·Registry·Secure System / **System·System Idle Process는 제외** — 작업 관리자도 이 둘은 표시한다). 테스트 **23 green**.
- 메인 화면 설정 메뉴에 **"의사 프로세스 숨기기"** 체크(기본 on), 끄면 즉시 목록 재구성. Top 5 팝업도 같은 규칙으로 숨김.

**교훈(재기동 절차 정정)**: 실행 중인 exe를 Windows가 잠그므로 `cargo build --release`를 먼저 하면 `os error 5`로 링크 실패한다. 더 위험한 건 **빌드 실패를 놓치고 옛 바이너리를 재실행**하는 것(이번에 실제로 한 번 발생 — 재기동은 됐으나 새 기능이 없는 바이너리였다). → [18 §3-1](../18-build-and-test.md) 절차를 **중지 → 빌드 → 실행** 순서로 정정.

## 12차 — 메인 화면(트리 그리드)·알림 이름·메뉴 정리 (사용자 요청 5건 연속)

**사용자 요청**: ① 알림에 `mk-app.exe` 대신 제품명 표시 ② 우클릭 "Top 5 보기"는 좌클릭과 중복 → "목록 보기"로 바꾸고 **전체 목록** 표시 ③ 좌클릭 팝업 버튼은 **지금 정리·목록 보기 2개만**(설정은 우클릭 전용) ④ 목록 창이 **메인 화면** — 상단 메뉴(환경 설정·자동 실행 등) + **그리드·헤더 클릭 정렬** ⑤ 좌측 확장 버튼으로 **쓰레드·프로세스 트리** 전개 + **프로세스/트리/쓰레드 종료**.

**구현**:
- **DR-12 알림 이름**: 빌드 스크립트(`build.rs`)가 Windows SDK `rc.exe`를 직접 찾아 VERSIONINFO를 임베드(외부 crate 0 — DR-5 유지, rc.exe 없으면 조용히 건너뜀). 배포 파일명도 `NexaMemKeeper.exe`로 변경(`[[bin]] name`). 실측: `FileDescription = Nexa MemKeeper` 확인.

- **종료 3종**: 프로세스(2단계) · **프로세스 트리**(자손을 잎부터 역순 종료 — 부모가 죽는 사이 자식이 되살아나는 것 방지) · **쓰레드**(경고 문구 포함 확인). 보호 대상은 메뉴가 비활성.

- mk-core에 트리 로직 이관(테스트 가능): `build_rows`(펼침 상태 반영 평면화·고아 보존·**순환 보호**), `descendants`, `sort_procs`, `ThreadInfo` — **테스트 22 green**.

**실측**: exe **0.41MB** · 상주 셸 유휴 **1.71MB** · 열거 500 프로세스 **7.5ms**(디버그) · 목록 창(워커) 열림 시 14.79MB → **닫으면 프로세스 종료로 전량 회수**(하이브리드 구조 DR-7의 실효 확인).

**사용자 질문 "Memory Compression 뭐야? 작업 관리자 목록과 왜 다르지?"** → 조사 결과를 [19 §4-5](../19-memory-measurement-and-reclaim.md)에 문서화. 요지: ① 압축 메모리 저장소 프로세스(WS 1,413MB / 프라이빗 바이트 10MB) ② 작업 관리자 **자세히** 탭이 의사 프로세스를 숨기는 것(PowerShell·Process Explorer에는 보임 — 우리 열거 500개 vs `Get-Process` 499개로 동일) ③ 정렬 지표 차이(우리=프라이빗 워킹셋, 작업 관리자=작업 집합) — `rust-analyzer`가 프라이빗 1,440MB/WS 503MB로 순위가 뒤집히는 실례. **버그 아님**.

## 11차 — M2 Top 5 팝업 구현·실측 (사용자 요청 "다음 진행")

**구현**: `procs.rs`(열거 1콜) · `popup.rs`(380×230 커스텀 드로잉 — 요약+사용률 바·Top 5 행·버튼 3·호버·더블버퍼·포커스 상실 시 닫힘·닫을 때 자기 트림) · 항목 우클릭 → 트림/종료(확인 후) → 워커 위임 · `worker`: `run_trim`/`run_kill`(WM_CLOSE 3초 대기 후 TerminateProcess).

**실측**:

**교훈(테스트 스크립트 함정)**: 트레이 콜백은 `WM_APP+1 = 0x8001`인데 검증 스크립트가 `0x0401`(WM_USER+1)로 보내 "팝업이 안 뜬다"고 40분 헤맸다. **코드가 아니라 테스트가 틀린 경우** — 진단 로그(`shell: WM_TRAY event=…`)를 넣고 나서야 메시지 자체가 도착하지 않았음이 드러났다. 디버그 빌드에 남겨 둔다.

**보호 목록 보강**: 커널이 보고하는 실제 이름이 `Memory Compression`(작업 관리자 표기와 동일)이라 기존 `memcompression` 항목으로는 매칭되지 않았다 → 두 표기 + `System`·`System Idle Process` 추가.

- 예산 재측정: **exe 0.34MB ≤3 · 유휴 RSS 2.20MB ≤5 · CPU 0.062s/60s** · 임포트 OS 인박스 8종(advapi32 추가 — 토큰 특권). 전 게이트 유지.

**교훈 2건**:
1. **PowerShell로 GUI 서브시스템 exe의 종료 코드를 못 잰다** — `& $exe`가 대기하지 않아 항상 0. 릴리스 빌드 검증은 디버그 빌드(콘솔 있음)로 하거나 `Start-Process -Wait` 필요. 셸의 `Command::status()`는 서브시스템과 무관하게 정상 대기.
2. **영역②(스탠바이 퍼지)는 `Available` 수치를 올리지 않는다** — Standby도 Free도 모두 Available에 포함되므로(docs/19 §2-1) 퍼지는 Available 내부 이동일 뿐. 보고된 +209MB는 **영역①(트림)의 성과**다. 회수량 수식(docs/19 §4-3 = Avail 델타)은 트림 효과를 정직하게 반영하므로 유지 — 숫자 부풀리기가 없다는 점에서 오히려 적합.

## 3차 — 판단 우선순위 확정(DR-4) → ADR-0003 권고 정정 (사용자 확정)

**무엇**: 사용자 지시 "개발·배포의 편의성보다 성능·동작 안정성이 더 중요" → **DR-4로 고정**([10 §1](../10-decision-record.md)), [00 비전](../00-vision.md) 설계 원칙 0으로 반영.

**정정된 판정**:

- [ADR-0001](../06-adr-0001-stack.md): 권고 A(Rust) 유지·논거 강화 — C/C++ 대비 우위 축을 개발 편의가 아닌 **안정성**(수동 메모리 관리의 크래시 면적 vs 컴파일 타임 안전)으로 재정리. C#/Go 탈락 사유에 GC 정지·점유 변동(안정성) 추가.

**부수 이득 기록**: 하이브리드 구조에서 승격 필요 정리 영역(②~⑥)은 워커만 승격 가능 — 상주 셸은 항상 일반 권한 유지(08 §4-5).
