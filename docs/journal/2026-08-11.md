### 지적 내용 (2패키지 동일)

```
nexa-memkeeper has failed automated validation.
Requirements
  An email address was found in the field Description.
  An email address should not be part of a nuspec file.
Notes
  The package maintainer field (owners) matches the software author field (authors).
```

- **Requirements = 필수** — 고쳐야 승인된다. 원인은 설명 말미의 `— contact kiros33@sosomlab.com.`
  상업 라이선스 문의처를 nuspec 본문에 직접 적은 것. Chocolatey는 nuspec에 이메일이 들어가는 것을
  일괄 금지한다(수집 대상이 되고, 연락 창구가 패키지 메타데이터로 굳는다).
- **Notes = 선택** — `owners`(SosomLab)와 `authors`(SosomLab)가 같다는 지적인데, 실제로 동일 주체라
  고칠 것이 없다. 모더레이터가 사람 눈으로 확인하는 항목이라 그대로 둔다.

### 조치 ① 이메일 제거 — 연락처는 라이선스 문서로 넘긴다

두 nuspec의 설명 말미를 링크로 바꿨다. 연락처를 없앤 게 아니라 **한 단계 미룬 것**이라,
상업 라이선스 문의 경로는 그대로 살아 있다([LICENSE.md](../../LICENSE.md) 8행에 이메일·홈 URL).

```diff
-— contact kiros33@sosomlab.com.
+— see the [license](https://github.com/SosomLab/nexa-memkeeper/blob/main/LICENSE.md) for
+how to get in touch.
```

검증: 로컬 `choco pack`(v2.7.3) 2건 성공 → 만들어진 nupkg 안의 nuspec을 정규식으로 재검사,
**이메일 매치 0건**. `packaging/` 전체 재검색도 0건(winget 매니페스트에는 원래 없었다).

### 조치 ② 재제출 수단 — 태그 없이 **같은 버전**을 다시 올린다

여기가 핵심이다. 규정은 *"The exact same version should be uploaded during moderation review"* —
**0.7.1을 내는 게 아니라 0.7.0을 덮어써야 한다**. 새 버전을 내면 지적받은 0.7.0이 큐에 남아
이중 심사가 되고, 승인돼도 사용자에게는 고장난 설명이 딸린 버전이 남는다.

그런데 기존 `release.yml`의 choco 단계는 **태그 push에서만** 돈다 → 태그를 다시 달지 않고는
고칠 방법이 없었다. 그래서 [`choco-resubmit.yml`](../../.github/workflows/choco-resubmit.yml) 추가:

- `workflow_dispatch`(버전 입력, 비우면 최신 릴리스 태그).
- **릴리스 자산을 다시 받아 SHA-256을 계산**한다 — 재제출본이 최초 제출본과 같은 바이너리를
  가리켜야 한다. 저장소에 박아 둔 해시를 믿지 않는 건 `winget-submit.yml`과 같은 원칙.
- 게시 스위치 규약 동일: `CHOCO_PUSH=true` + `CHOCO_API_KEY`가 없으면 **nupkg만 만들고 멈춘다**.
- 모더레이션 중인 버전은 같은 번호로 덮어쓸 수 있다(승인 완료된 버전이면 409로 거부된다).

절차는 [20 §7-6](../20-packaging.md)에 SSOT로 남겼다.
